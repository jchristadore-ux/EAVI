# AV Environment Intelligence — session handoff

Read this first. It is the state of the project as handed over on 12 November 2026, and the rules that apply to
any further work. Open the session in this folder (the one that holds `app/`, `tests/`, `tools/`).

## What this is

A mobile-first, offline-first web application for auditing conference-room AV environments (buildings, floors,
rooms, devices, functional tests, findings, backlog, reports, daily export). Plain ES2017, classic scripts sharing
`window.EV`, **no dependencies and no build step for development**. Data lives in IndexedDB on the device.
`README.md` is the overview; `docs/ARCHITECTURE.md` is the engineering reference.

## Standing rules from the owner (do not relax these)

- Treat all audit information as potentially sensitive enterprise infrastructure data.
- Never hardcode credentials. No exposed API secrets.
- Do not expose private IP information or network topology publicly.
- Do not send client infrastructure data to external AI services without explicit authorization.
- No automatic network scanning, discovery or device configuration. It is a documentation tool.
- Never silently assume or invent missing values. Never turn a suspected cause into a confirmed one.
- Do not claim OCR, offline capability or anything else unless it is implemented and tested.
- Do not claim something is complete unless it has been tested.
- The application and its hosting must be approved by client security before real client infrastructure
  information is entered. As of this handoff that approval has **not** been recorded anywhere in the project.

## Working on this machine (Windows 11, PowerShell 5.1)

- Not installed: Node, npm, gh, Python, Docker, pwsh. Git is available only through GitHub Desktop (see below).
- Tools are PowerShell scripts. `.ps1` files must be ASCII only (PowerShell 5.1 reads them as ANSI).
- Source files use LF line endings and UTF-8 without a byte-order mark.
- The Glob and Grep tools fail here (ripgrep missing): search with `[System.IO.File]::ReadAllLines` and `-match`.
- Very long paths break `Get-Content`, `Test-Path` and friends: use `[System.IO.File]` with a `\\?\` prefix.
- Excel (COM) and the Windows PDF engine are available and used to validate generated files.

## Commands

```
powershell -ExecutionPolicy Bypass -File tools\build.ps1          # build dist\ (run before the tests)
powershell -ExecutionPolicy Bypass -File tools\serve.ps1          # dev server on http://localhost:5173
powershell -ExecutionPolicy Bypass -File tools\validate-outputs.ps1   # check the files the tests generated
```

- Application: `http://localhost:5173/app/` · Tests: `http://localhost:5173/tests/tests.html`
- The suite must be green before anything is called done. It reads build output, so build first. In a hidden
  browser window it takes several minutes (timers are throttled); in a visible one about a minute.
- After changing `app/js/schema.js`: open `tools/gen-schema.html` through the dev server and copy
  `.testout\schema.sql` over `supabase\schema.sql` (a test fails if they differ).

## Conventions that matter

- No third-party code, no external requests. The production page's Content-Security-Policy is
  `connect-src 'self'`; `tools\build.ps1 -SyncOrigin https://<project>.supabase.co` is the only way to open one origin.
- A new record has nothing pre-filled that the auditor did not enter. Missing values stay missing and are flagged.
- Record content is never markup: only nodes made by `EV.h` render as elements.
- Deleting is a soft delete (`deleted_at`); a deleted photograph also loses its image files.
- Every behaviour change gets a test in `tests/suite.js` and, where a document describes it, a document edit.
  Documents state only what the code does and what was actually tested.
